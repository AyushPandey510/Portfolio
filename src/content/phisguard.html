PhisGuard

A browser extension that scores the page you just opened from 0 to 100 for phishing risk, before you type anything.

6 min read Python, Flask Chrome MV3 scikit-learn Docker

Problem

Phishing pages look right. People need a warning on the page itself, at the moment they arrive.

My role

Everything: Flask API, risk model, email-text classifier, Chrome extension, admin dashboard.

Result

One score from six signal groups, including Google Safe Browsing and VirusTotal, with a feedback loop for retraining.

01

Why I built it

Most phishing checks happen in the inbox, but the damage happens on the page. By the time you're on a fake login screen the email is forgotten, and the page looks exactly like the real one.

PhisGuard sits in the browser. Each time a page finishes loading, the extension asks the API about the URL and shows a warning if the score is high. A separate comprehensive check also covers SSL, redirects, known breaches and the text of a suspicious email.

Warn on the page, not in a report afterwards.

03, the hard part

Many weak signals, one honest number

No single check is reliable. A missing certificate might be a lazy site, not a scam. A URL shortener might be a newsletter. Safe Browsing only knows about pages someone has already reported. So each group produces its own score, and the risk scorer combines them with fixed weights.

Inside the URL group, rules add points for things phishers rely on: an IP address instead of a name (+25), a suspicious top-level domain (+20), a link shortener (+20), login-style keywords (+15), no HTTPS (+10). A Safe Browsing match adds 50, and a malicious VirusTotal verdict adds 70.

Where machine learning fits today

The email-text classifier runs in every comprehensive check. A Random Forest for URLs is trained from PhishTank data and managed through admin endpoints (versions, switch, retrain), but the live URL score doesn't use it yet. Wiring it in is first in section 06.

Inside the extension

An extension that calls an API on every page load can easily hammer it. The service worker filters before it asks anything.

1
ChrometoService worker

A page finishes loading, or a single-page app changes its URL.

2
Service worker

Skip chrome://, about:, file:, data: and javascript: URLs, and anything that isn't a real domain.

3
Service worker

Skip URLs checked recently, wait at least 2 s between checks, and answer from the local cache when it can.

4
Service workertoAPI

POST /check-url and get the score and the reasons behind it.

5
Content script

Show a warning on the page when the risk is high.

06

What I'd change next

Use the URL model live

Blend the Random Forest's probability into the URL score instead of only managing it from the admin side.

Passwords never leave the browser

Switch breach checks to k-anonymity: send the first 5 characters of a hash and compare the rest locally.

Run outside checks in parallel

Safe Browsing, VirusTotal, SSL and redirects run one after another; running them together cuts the wait.

Fewer false alarms

An allowlist of the most-visited domains, so big sites with long URLs don't get flagged.
