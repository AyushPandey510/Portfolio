01

How it works

This is retrieval-augmented generationFind the most relevant passages first, then ask the language model to answer using only those passages. in its smallest honest form: two pipelines, one run once per document and one run per question.

02, the hard part

Teaching a model to say "I don't know"

Language models would rather guess than stay quiet. There are two guards. Retrieval refuses first: if even the closest chunk is farther than 1.5 in embedding space, it returns nothing at all, so there is nothing to build an answer from. Then the prompt sets strict rules and a fixed sentence for when the answer isn't present.

rag/retriever.py

distances, indices = index.search(np.array(query_embedding), k)
results = [chunks[i] for i in indices[0]]

# basic hallucination control
if distances[0][0] > 1.5:
    return []

rag/generator.py, the prompt

You are a strict question answering system.
Answer ONLY from the given context.

Rules:
- Do NOT use outside knowledge
- If answer is not present, say:
"The answer is not available in the provided document."

Only the two best chunks go into the prompt. Fewer, closer passages give the model less room to wander.

04

What I'd change next

Cite the page

Keep page numbers with each chunk and show them next to the answer.

Measure refusals

A small question set with known answers, to tune the 1.5 cut-off with numbers instead of feel.

Chunk by meaning

Split on sentences and headings so a chunk never starts mid-thought.

Stream the answer

Show tokens as Llama 3 writes them, so a slow laptop feels faster.
