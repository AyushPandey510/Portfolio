01

Why I built it

"Can you look at what I've got so far?" is a normal question in a lab or an office. Answering it with Git means a commit called "wip", a push, a branch, and a cleanup that never happens. Pasting a diff into chat loses binary files and leaks whatever secrets were in it.

ChangeShare sends your working changes, a stash or a commit straight to another computer on the same network. The receiver sees exactly what will change, applies it as uncommitted edits, and can undo it.

Share the work, not the history.

02

The architecture

The CLI is the whole engine. The VS Code extension is only a user interface over it, so there is one protocol and one place for bugs.

03, the hard part

A spoken code that never crosses the wire

The code is short so people can say it aloud. Short codes are easy to guess, and anyone on the same Wi-Fi can watch the traffic. So the code is never sent. Both sides use it in a PAKEPassword-authenticated key exchange: two parties who share a short secret agree on a strong key without revealing the secret. called CPace, and only a device that knows the code ends up with the same session key.

src/transfer.ts

function key(code: string, salt: Buffer) {
  return scryptSync(code, salt, 32, {
    N: 1 << 15, r: 8, p: 1,
    maxmem: 64 * 1024 * 1024,
  });
}
// ...
const session = cpace.ristretto255.init({ PRS: codeKey, sid, CI });

Four more locks on the door

1
Sender

Listens only on a private or link-local address, never on the public internet.

2
Sender

Must approve each receiver by hand before the handshake starts.

3
Sender

Allows exactly one successful delivery, then shuts the listener down.

4
Sender

Expires after the configured number of minutes, even if nobody connects.

04

Not touching your Git

To capture untracked files in a patch you normally have to git add them, which changes what you've staged. ChangeShare points GIT_INDEX_FILE at a temporary index, loads HEAD into it, adds the working tree there and diffs that. Your real staging area is never touched, and the temporary index is deleted even if Git fails.

src/git.ts

await git(["read-tree", "HEAD"], root, { GIT_INDEX_FILE: index });
// add the working tree to the temporary index, then:
await git(["diff", "--cached", "--binary", "--full-index",
           "--no-ext-diff", "HEAD"], root, { GIT_INDEX_FILE: index });

Before anything is sent, filenames are checked against a denylist (.env*, *.pem, *.key, id_rsa*) and added lines are scanned for private keys, AWS keys, GitHub tokens and password-like assignments. Findings are shown to you rather than silently dropped.
